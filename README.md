# منصة الأكاديميات

منصة عربية (RTL) لإدارة الأكاديميات وحلقات القرآن والدروس: الأعضاء والصلاحيات، والطلاب والحلقات، والحصص والحضور والتقييمات، وCRM للمسجلين الجدد، والمحادثات، والملفات التعليمية، والإشعارات.

## المكونات

- **الواجهة:** React 19 + Vite + Tailwind CSS 4 + TypeScript.
- **الخلفية:** Firebase Auth و Firestore و Storage و Cloud Messaging، مع واجهات API بسيطة تعمل على Express محليًا وعلى Vercel Functions في الإنتاج.
- **الأمان:** قواعد Firestore تبدأ بالرفض الكامل، والأدوار والصلاحيات تُكتب من السيرفر فقط عبر Firebase Admin، وكل أكاديمية معزولة عن غيرها.

## الأدوار

| الدور | ما الذي يستطيعه |
| --- | --- |
| مدير الأكاديمية (owner) | كل شيء. لا يمكن إنشاء مدير آخر من أي واجهة. |
| مشرف (supervisor) | صلاحيات محددة يمنحها المدير: الطلاب، المعلمون، الحلقات، أولياء الأمور، CRM، التقارير. |
| معلم (teacher) | طلابه وحلقاته، رفع الملفات لحلقاته، إشعارات لطلابه وأولياء أمورهم فقط. |
| طالب (student) | بياناته وحضوره وتقييماته وملفات حلقته. |
| ولي أمر (parent) | بيانات أبنائه المرتبطين به فقط. |

## المحادثات

- محادثات فردية ومجموعات، مع قائمة بآخر رسالة وعدد الرسائل غير المقروءة.
- جهات الاتصال تعرض **الاسم والدور فقط**. لا تظهر أرقام الهواتف ولا البريد في المحادثات.
- الرسائل تُكتب من السيرفر فقط، والمحادثة الفردية بين شخصين لها محادثة واحدة فقط.

## مستحقات المعلمين

- المدير والمشرف يحددون ريت الساعة لكل معلم من شاشة "المستحقات والتقارير".
- كل تقرير حصة مكتمل يحسب مبلغه = الريت × المدة (بالساعات)، ويُحفظ الريت وقت التسجيل، فتغيير الريت لاحقًا لا يغيّر التقارير السابقة.
- المبلغ يتوزع بالتساوي على الطلاب الحاضرين (حاضر أو متأخر)، والحصة بلا حضور تظهر كـ"غير موزع".
- المعلمون والطلاب وأولياء الأمور لا يرون الريت ولا المستحقات.
- للحصص القديمة قبل هذا التحديث: زر "احتساب الحصص القديمة" يحسبها بالريت الحالي.

## تشغيل المشروع محليًا

1. انسخ `.env.example` إلى `.env` واملأ القيم.
2. ثبّت الحزم:
   ```bash
   bun install
   ```
3. شغّل بيئة التطوير:
   ```bash
   bun run dev
   ```
4. أنشئ أول مدير للأكاديمية (مرة واحدة فقط):
   ```bash
   bun run seed:owner
   ```

## أوامر مفيدة

| الأمر | الوظيفة |
| --- | --- |
| `bun run dev` | تشغيل السيرفر والواجهة للتطوير |
| `bun run typecheck` | فحص الأنواع |
| `bun run test` | اختبارات الصلاحيات وواجهات الـ API والمحادثات |
| `bun run build` | بناء الواجهة والسيرفر |
| `bun run start` | تشغيل النسخة المبنية (`dist/server.js`) |

## النشر

- **قواعد Firestore والفهارس وStorage:** عبر GitHub Actions (`Deploy Firestore Rules`) أو `firebase deploy --only firestore,storage`.
- **الواجهة والـ API:** Vercel. ضع متغيرات `VITE_*` للواجهة، ومتغيرات `FIREBASE_*` السرية للخادم فقط.

## متغيرات البيئة

- `VITE_*`: إعدادات Firebase العامة للواجهة، ويجب أن تكون آمنة للعرض.
- `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `FIREBASE_DATABASE_ID`: للخادم فقط. لا تضعها بادئة `VITE_` أبدًا.
- `BOOTSTRAP_*`: مؤقتة، لسكربت إنشاء أول مدير. احذفها بعد الاستخدام.

## الاختبارات

- `tests/security.policy.test.ts`: اختبارات منطق الصلاحيات.
- `tests/api.security.test.ts`: سيناريوهات الهجوم من `security_spec.md` على مستوى الـ API، واختبارات المحادثات والملفات، وتعمل على قاعدة بيانات وهمية في الذاكرة.
- قواعد Firestore و Storage لم تُختبر آليًا بعد. الخطوة التالية المقترحة: اختبارها عبر Firebase Emulator.

## ملاحظات أمنية

- لا توجد حدود معدل (rate limiting) على واجهات الـ API حاليًا.
- كلمات المرور لحسابات الطلاب وأولياء الأمور يحددها المشرف، ولا يُجبر النظام على تغييرها عند أول دخول.
- ملف `firebase-applet-config.json` يحتوي مفاتيح Firebase العامة، وهي آمنة للعرض، والحماية الحقيقية في القواعد.
